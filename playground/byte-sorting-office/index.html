Files, folders and binaries, shown on my own Mac

Your disk is a sorting office

Inside a Mac's drive there are no files and no folders. Mine holds about 243 million numbered boxes, each holding exactly 4,096 bytes (4 KB). Names, folders and programs are all bookkeeping, kept by a clerk called the file system. The clerk's one job is to remember which boxes belong to which name.

A binary is one kind of parcel in those boxes: a program written in the chip's own language instead of in words for you. The seven counters below build up to it, one idea each.

    Counter 1

    A folder is a register. A path is an address.

    A folder does not hold files inside it. It is a register: a list of names, and beside each name the number of that file's index card. The card holds the facts: size, owner, permissions and which boxes hold the contents. Computers call the card an inode (say "eye-node", short for index node).

    A path such as /Users/triyambak/.dotfiles/rebuild.sh is a postal address, read left to right. The clerk opens the top register, finds the next name, follows its card number to the next register, and repeats until the address runs out. Walk it yourself. The card numbers are the real ones from my Mac.

    Counter 2

    What the clerk does when you move, copy or delete

    Every everyday action is a change to the register, to the boxes, or to both. That one fact explains why some actions are instant and others take minutes. Press an action to see what really changes. The three files are examples.

    Counter 3

    Open any box and you find bytes

    A byte is a row of eight switches, each on or off. Eight switches give 256 possible patterns. On its own a byte means nothing. It becomes a number, a letter or a colour only when a program decides how to read it.

    Programmers write a byte as two symbols from 0 to 9 and A to F. This shorthand is called hex, and it is how the rest of this page shows bytes. Flip the switches.

    Counter 4

    Same kind of bytes, two kinds of file

    These are the first 32 bytes of two real files on my Mac, exactly as they sit in their boxes. Under each byte is the letter it stands for, if it stands for one. The dots are bytes with no letter.

    One file turns into words you can read. The other turns into dots, because it was never meant for you. That is the whole difference between a text file and a binary file: in a binary, the bytes are not letters.

    ~/.dotfiles/rebuild.shtext file · 2,332 bytes · a script
    gitbinary file · 4,102,416 bytes · a program

    Read across the top row: #!/usr/bin/env bash, then a line break (0A), then set -euo pip. The git row reads as nothing at all.

    Counter 5

    The first bytes are the postmark

    Most file types begin with a fixed signature, like a postmark on an envelope. Programmers call it the magic number. The ending of a file's name, such as .xlsx, is only a label anyone can retype. The postmark is inside the file, and it tells a program what it is really holding.

      Counter 6

      So what is a binary?

      A binary is a program file whose boxes hold instructions in the chip's own language. People write programs in words, called source code. A translator program called a compiler turns those words into the chip's instructions, once, ahead of time. The result runs straight on the chip, which is why it is fast and why you cannot read it.

      Each kind of chip speaks its own language. My Mac has an Apple chip (the family is called arm64); older Macs had Intel chips (x86_64). Switch the chip and watch the same instruction change.

      Folders named bin, such as /bin, /usr/bin and /opt/homebrew/bin, are where these programs live. bin is short for binaries. Scripts live there too, so people say "binaries" loosely for any command you can run by name. What every one of them needs is the x (execute) permission from Counter 1.

      Counter 7

      You type git. Which copy runs?

      When you type a command, the shell (the program that reads what you type in the terminal) does not search the whole disk. It checks a short list of folders, in a fixed order. That list is called the PATH. The first folder holding a runnable file with that name wins, and the search stops there.

        The words, once more

        Byte
        Eight on/off switches. One of 256 patterns.
        Hex
        A byte written as two symbols, from 00 to FF.
        Block box
        A fixed-size slot on the disk. 4,096 bytes on a Mac.
        File system
        The bookkeeping that maps names to boxes. A Mac's is APFS, the Apple File System.
        Folder directory
        A register of names, each pointing to an index card.
        Inode index card
        One per file: its size, owner, permissions and list of boxes.
        Path
        A file's address: folder names joined by /, read left to right.
        Permissions
        The r (read), w (write) and x (execute) stamps, for owner, group and everyone.
        Symlink shortcut
        A tiny file whose only content is another address.
        Binary
        A file whose bytes are not text. Usually means a program in the chip's own language.
        Script
        A program kept as readable text, read line by line by another program such as bash.
        Compiler
        The translator that turns source code into a binary for one kind of chip.
        Magic number postmark
        The fixed first bytes that tell a program what kind of file it holds.
        Shell
        The program that reads what you type in the terminal. On a Mac it is zsh.
        PATH
        The ordered list of folders the shell searches for a command. First match wins.
