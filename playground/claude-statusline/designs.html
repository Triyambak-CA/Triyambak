Chosen 02-Oct-2026: the pace bar with the forecast sentence (design 3's bar, design 4's words, for both windows). It is what my status line script now prints, in these exact colours, and it stays within 93 columns. When a window would run dry, the sentence also says when it refills. The first draft's dots answered "how much have I used?"; this also answers "at this rate, will I run out before it refills?", by comparing the share of the limit used with the share of the window that has passed. 48% used when only 31% of the five hours has gone means spending about 1.5 times faster than the limit allows. The designs under "Considered, not chosen" stay as the working behind the choice.

What a terminal allows

why no spinning wheel

Hard limits every design here respects

  • Text only, one colour per character. A braille character holds a 2 by 4 grid of dots but takes one colour, so where a wheel's filled arc meets its empty track, the colour changes on a character boundary, up to one character late.
  • Nothing moves. The line redraws after each message and every 60 seconds. A wheel can show where it stands, never turn.
  • Claude Code strips spaces at the start and end of each row. A circle's top row starts with empty space, so the wheels fill it with the invisible braille character instead, which is not counted as a space and keeps the circle from shearing left.

Costs to weigh

  • Every row is a row of conversation you lose. The chosen design uses 3, the wheels 5, the one-liner 1.
  • History needs a small file. Claude Code only sends the current numbers. The sparkline and the ledger's "lately" column need the script to jot each reading into a log file, a few hundred bytes a day. Their history here is simulated.
  • Braille depends on the terminal. My terminal, WezTerm, draws braille itself rather than from a font (its built-in block glyphs, on by default), spreading the eight dots across the whole character, and the wheels here are drawn that way. A browser or another terminal using a font shows smaller, bunched dots, and the circles look broken there. Check once in the real terminal before choosing a wheel.

Times are worked out from your device's clock. Pace assumes you keep using the limit at the average rate so far in the window, so it says "too early to tell" during the first tenth of a window, when one busy burst would make the forecast meaningless. Context and folder are shown only to frame the rows; they are not the subject of the mock.
